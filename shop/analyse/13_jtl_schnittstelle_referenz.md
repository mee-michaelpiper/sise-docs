## 2. Anfrage-Grundlagen

| Header | Wert | Hinweis |
|---|---|---|
| `Authorization` | `Wawi <token>` | Token der App-Registrierung; **kompromittiert, wird getauscht** (Bericht 12, 3.4) |
| `X-AppId` | `icsWebshop/v1` | Name der registrierten App (vom Alt-Dienstleister). Bei Neuregistrierung eigene App-ID, z. B. `MeesenburgShop/v1` |
| `X-AppVersion` | `1.0.0` | |
| `Accept` | `application/json` | |
| `x-runas` | (optional) | laut Spezifikation 1.1 für Benutzerkontext; bisher ungenutzt |

- Pfade **mit und ohne `/v1`** liefern heute identische Antworten (geprüft 08.10. an Artikel 7 und 71679). Das neue Backend nutzt durchgängig `/v1/…`.
- Paging: `pageNumber` (ab 1), `pageSize`; Antwort `{ Items, TotalItems, HasNextPage, NextPageNumber, … }`. 200 je Seite funktionieren (≈ 20 s je Seite im Shop-Kanal über den Tunnel).
- Fehlerformat: `{ "ErrorCode", "ValidationErrors", "Errors", "ErrorMessage", "Stacktrace" }`, teils mit Tippfehler `"Unkown"`. API-Versionsfehler kommen in einem anderen Format: `{ "Error": { "Code", "Message" } }`.
